# 整组实验功能升级说明

## 功能与入口

学员进入逻辑原理后选择装置，在“基础逻辑”“组合逻辑”旁选择“整组实验”。必须选择序列 1、2，序列 3 可选。每个位置只显示管理员配置的对应序列逻辑。

选择确认后保存组合，但只有监测端接受启动后才出现在最近使用列表。列表按当前学员、当前装置保留最近使用的五种不同组合；重复使用置顶，不删除其他组合或运行记录。

历史重开使用最新引导、装置基准和逻辑勾选；序列或归属改变后不合法的组合只能查看历史，不能继续启动。实验记录保存运行时的成员名称和顺序。

## 合并规则

- 引导只显示已启用且允许在整组实验显示的条目，按基础逻辑序列及原条目顺序排列。
- 定值整定最多保留一个，归入最后一个逻辑；不存在可显示定值条目时不自动生成。内容仅为校验项目并集。
- 定值、软压板、硬压板分别按引用取勾选并集；统一使用装置基准，不改写原配置。
- 电压与电流分别合并。相同端子映射去重，三相覆盖其兼容单相子集；不同端子组仍须全部校验。“不接线”表示无要求，不表示禁止接线。

## 数据库与部署

1. 停止旧服务，备份业务库，再同步部署后端和前端；不要修改只读屏柜库。
2. 新增三张业务表：whole_experiment、whole_experiment_member、whole_experiment_run，不改写现有管理员组合及实验记录。
3. 启动时 WholeExperimentSchemaMigrator 执行 V23__whole_experiments.sql，使用幂等建表，兼容生产 ddl-auto: none。数据库账户需要建表权限，迁移失败会阻止启动。
4. 可在部署前由数据库管理员执行同一 SQL；重复执行不会清空数据。
5. 核查两个必选序列已有候选逻辑，并验证一个两成员、一个三成员组合。

回退应用版本时保留三张新增表即可，旧版本不读取它们；不要删除整组记录。若部署中途失败，先核对建表结果后重试。

## 接口

- POST /api/whole-experiments：请求包含 deviceId、logicDiagramIds，服务端校验、按序列排序并创建或复用组合。
- GET /api/whole-experiments/recent?deviceId=...：最近五种组合。
- GET /api/whole-experiments/{id}、GET .../{id}/guide、POST .../{id}/precheck：详情、引导、联合校验。
- POST .../{id}/monitor：请求包含 action（start、heartbeat、end、abort）；非 start 操作必须包含 taskUuid。
- GET .../{id}/runs：整组运行记录。
- GET /api/whole-experiment-runs/{taskUuid}、GET .../{taskUuid}/members、GET .../{taskUuid}/members/{logicDiagramId}：持久化结果、成员摘要与成员断面。

接口从登录身份确定学员，禁止读取或控制其他学员的组合和任务。启动接口会再次进行服务端联合预校验。

## 监测与恢复

沿用 summon_logic_group_monitor，发送一个 ied_name 和按序列排列的 logic_ids。心跳、结束及中止命令不变，不引入逐个通过的串行监测规则。

运行上下文在下发前提交。启动拒绝显示为 START_FAILED；等待响应超时显示为 RESPONSE_TIMEOUT，不能视为设备已停止，也不会自动重试启动。重复回调幂等处理，迟到接受不会覆盖终态。刷新详情恢复轮询及心跳；完成消息丢失时可通过监测任务表中的同一 UUID 恢复状态。

仍需真实环境联调：确认 monitord 使用请求 UUID 关联 monitor_task，接受两成员及三成员有序列表，返回 v3.0 logic_group_snapshot_v1 断面；验证相序、停止及成员回放。没有有效断面时只显示记录及原因，不允许进入回放。

## 本地验证

后端执行 mvn test；本地若默认编译器与 Java 8 不一致，显式指定 Java 8 编译器：

    mvn -Dmaven.compiler.fork=true -Dmaven.compiler.executable=/实际的Java8路径/bin/javac test

前端执行 npm run test:whole、npm run test:setting、npm run test:sampling 和 npm run build。页面假数据冒烟测试不能替代真实装置联调或生产数据库升级验证。
