# 统一定值与整组试验配置升级说明

## 升级步骤

1. 停止旧版本业务服务，备份业务库 `ct-screen-monitor`，尤其是 `setting_list_item`、`experiment_guide_items` 和 `logic_learning_configs`。
2. 同步部署新版后端及前端。启动迁移需要业务库的建表、加列及读写权限，屏柜库仍只需查询权限。生产环境 `ddl-auto: none` 也由现有启动迁移完成新结构创建。
3. 启动时先创建 `logic_setting_selection`、`business_migration_state`，并为引导和基础逻辑配置添加新字段，再执行历史勾选转换。数据转换及完成标记在同一业务事务中提交；失败会阻止启动，排除问题后可重试。
4. 确认日志出现“逻辑定值校验选择迁移完成”，且 `business_migration_state` 中 `unify_logic_settings_v21` 的 `completed` 为 `1`。检查日志中的“旧定值不在装置清单中”及“装置暂无定值清单”提示，按需在装置层补充项目，再配置逻辑勾选。
5. 抽查一条基础逻辑、一条组合逻辑：定值与装置一致，逻辑数值不可编辑，勾选可独立保存。修改装置值后重新打开逻辑确认同步。

可选择先手动执行 `src/main/resources/db/migration/V21__unify_logic_settings.sql` 完成结构升级；脚本末尾的两条 `ALTER` 仅对尚未添加相应列的数据库执行。应用启动迁移会检查列是否存在，不重复加列。SQL 本身不完成跨库历史选择转换，仍需启动新版应用；不要手动设置完成标记。

## 历史数据规则

- 有旧逻辑独立清单：按定值引用保留其中已勾选且仍在装置清单中的项目；旧数值不再使用，也不写回装置。
- 无旧逻辑独立清单：沿用升级时装置层的勾选。
- 新建逻辑及装置后续新增项目：默认不勾选。装置删除项目时清理相关逻辑选择；整套替换清单时按引用保留仍存在的选择。
- 旧逻辑层 `setting_list_item` 行保留追溯，运行时及配置复制不再使用。不要删除迁移完成标记，否则可能再次套用历史勾选。
- 引导的 `showInWholeExperiment` 默认 `true`，普通引导仍按原有启用规则显示；基础逻辑的 `wholeExperimentSequence` 默认 `1`，只接受 `1、2、3`，不改变普通列表排序。

## 接口变化

- 基础逻辑、组合逻辑查询仍使用原清单 GET 接口；`configuredItems` 为空，`effectiveItems` 为装置完整清单，项目的 `compareEnabled` 为当前逻辑勾选，来源指向装置。
- 保存逻辑勾选使用 `PUT /api/{admin|teacher}/setting-lists/{scopeType}/{scopeId}/selection`，请求如 `{"settingRefs":["定值引用"]}`，空数组表示不校验任何定值。
- 旧清单 PUT、DELETE、召唤、导入、导出操作仅允许装置作用域，逻辑作用域返回 400 和中文说明。
- 基础逻辑序列使用 `PUT /api/admin/logic-learning/logics/{id}/whole-experiment-sequence`，请求如 `{"wholeExperimentSequence":2}`。列表及详情响应返回该字段。
- 引导创建、更新及响应增加 `showInWholeExperiment`；更新时省略该字段会保留已有值。

## 软、硬压板统一基准与列表统一保存（V22）

软、硬压板现在同样只在装置层维护一套基准，逻辑层仅保存校验选择。装置保留召唤、导入导出、基准状态编辑及排序；逻辑层这些操作返回中文错误。逻辑未勾选任何压板时跳过对应校验。

启动迁移创建 `logic_pressboard_selection`，通过 `pressboard_kind` 区分软、硬压板，使用独立标记 `unify_logic_pressboards_v22` 一次性转换历史勾选。已有独立清单保留仍属于装置清单的勾选；原装置回退逻辑沿用升级时的装置勾选；新逻辑、新增项目默认不勾选。旧独立压板行仅保留追溯，配置复制改为复制新的选择引用。迁移不改变装置基准状态，也不向只读屏柜库写入数据。

可提前执行 `V22__unify_logic_pressboards.sql` 创建新表，历史数据仍由应用启动迁移；不要手动修改完成标记。升级备份应同时包含 `soft_pressboard_list_item`、`hard_pressboard_list_item` 和选择表。

- 软压板选择接口：`PUT /api/{admin|teacher}/soft-pressboard-lists/{scopeType}/{scopeId}/selection`。
- 硬压板选择接口：`PUT /api/admin/hard-pressboard-lists/{scopeType}/{scopeId}/selection`，沿用现有管理员权限。
- 选择请求：`{"pressboardRefs":["压板引用"]}`，空数组表示全不选。各逻辑的勾选独立于装置层和其他逻辑。
- 基础逻辑统一保存：`PUT /api/admin/logic-learning/logics/by-device/{deviceId}/configs`，请求 `{"items":[{"logicDiagramId":10,"sortOrder":20,"wholeExperimentSequence":2}]}`。页面仅提交已修改条目，一次业务事务保存排序及序列；校验失败则全部不保存。按最终状态检查排序冲突，支持两条逻辑交换序号。未修改的历史重复默认排序允许保留。
- 基础逻辑列表只保留顶部“保存修改”按钮，失败保留编辑内容，离开前提示未保存修改。

## 验证与回退

前端执行 `npm run build`、`npm run test:setting`。后端使用 Java 8 执行 `mvn test`；若本地 Maven 内嵌编译器无法识别 Lombok 生成的方法，使用 `mvn -Dmaven.compiler.fork=true test` 启用独立编译器。

本次没有新增整组试验入口；定值、软压板和硬压板均已统一为装置基准及逻辑选择。回退旧版本会恢复使用旧逻辑独立数值，无法解释新版选择表；需要回退时应停服并同时恢复升级前业务库备份及前后端版本。
